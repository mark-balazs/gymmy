gymmy follows dextra's Requirement Lifecycle and playbooks but stays off dextra's records: it is in no DI registry and nothing about it is written on DI pages, so skills in the repository load each playbook with gymmy's extension. Topics are ideas in the Jira Product Discovery space gymmy-roadmap (GR), each GYM epic implements one, and GYM has 123datei's delivery statuses: a story walks them from Non-tech refinement, a bug or task starts at To Do, and five are never used. Discovery, non-tech refinement and, for stories, test design run; tech refinement and the technical check wait for the architecture docs (GYM-106); building follows the Implementation playbook, with gymmy's own working rules as its exceptions. A Confluence page that holds a diagram is changed only by node edits that leave the diagram alone.

Product discovery reads GR's statuses as 123datei reads its roadmap's (new is Backlog, drafting Ideation, with the client Planning / Refinement, accepted Ready for implementation, delivered Done, dropped archived), and the client is Mark, who holds every PO, PM, RE and TL role. A learning about a process stays in gymmy's own queue, for Mark to carry over by hand. Behaviour checks run on production with the demo account, which Mark signs in to; until production has one (GYM-38), they run on a local copy of production's version and count as checked, the docs move's included; once it has one, those pages are checked there too (D-028). Each idea has a type (Feature, Business or Maintenance); a second space for technical health was rejected. What is not set up yet sits under the epic GYM-96.

A story walks Non-tech refinement → Test Design → Tech refinement → Tech check → To Do → In Progress → IN REVIEW → Done, going from Test Design straight to To Do until GYM-106 is done; a bug or task walks To Do → In Progress → IN REVIEW → Done. The five never used are Estimation, Local Demo, In Dev Testing, Dev Test Passed and In Qa Testing, and IN REVIEW is read as the pull request being open and in review.
