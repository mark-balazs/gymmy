  P->>UI: Taps Log set
  UI->>M: One write path, always
  M->>L: Stamp updatedAt, write row, queue outbox
  L-->>UI: Live query fires
  UI-->>P: The set is there — no network involved
  Note over S: ~800ms debounce
  S->>API: Outbox + highest seq seen
  API-->>S: Rows newer than that, across all tables
  S->>L: Apply server rows
  S->>L: Re-apply the outbox on top
  Note over S,L: Without that last step, a pull in flight overwrites<br/>a set logged while it was travelling

  participant C as Client
  participant API as POST /api/sync
  participant DB as Postgres

  C->>API: since = 12480, mutations[]
  API->>DB: Validate, upsert, stamp seq from one shared sequence
  DB-->>API: Rows newer than 12480, paged at 500 per table
  Note over API: logs filled their page at seq 13000<br/>profile has rows out at seq 17000
  API-->>C: cursor = 13000, hasMore = true
  Note over C,API: The cursor is held DOWN to the last row actually sent.<br/>Taking the highest seq would skip every log in between — silently, permanently.
  C->>API: since = 13000
  API-->>C: The rest, hasMore = false
